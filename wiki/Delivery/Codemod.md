A **codemod** is a script that modifies source code automatically, usually to make the same change in many places at once. Renaming a function and every call to it, switching from one library's API to another's, or updating code for a new language version are typical jobs. In a large codebase such a change might touch thousands of files, which by hand would take weeks and introduce mistakes.

The simplest codemods are search and replace with regular expressions; see [[Regular Expression]]. That works for trivial renames but breaks quickly, because text patterns can't tell code from comments or strings, can't match a call that spans several lines, and don't know which of two identically named functions is meant.

Serious codemods work on structure instead. The tool parses each file into an abstract syntax tree, finds nodes matching a pattern, rewrites those nodes, and prints the tree back out as code; see [[Abstract Syntax Tree]]. The hard part is the printing. A naive printer would reformat the whole file, burying the real change in thousands of lines of whitespace noise. Good codemod tools reprint only the nodes they changed and leave the rest byte for byte, or run a formatter over everything afterward so the noise is consistent; see [[Code Formatter]] and [[Diff]].

Facebook released a tool called codemod around 2009 for regex-based bulk edits, and later jscodeshift, which applies JavaScript transformations to syntax trees and became widely used in that ecosystem. Framework maintainers now often ship codemods with major releases, so users can upgrade across breaking changes by running a command; see [[Backward Compatibility]].

At the largest scale, Google has described a system for **large-scale changes** across its single repository: a change is generated by a tool, split automatically into many small pieces by directory, reviewed by the owners of each area, tested and merged separately; see [[Monorepo]] and [[Code Review]]. Splitting matters because one enormous change is nearly impossible to review and likely to conflict with work in progress; see [[Merge Conflict]].

Codemods make some practices viable that wouldn't be otherwise. Deprecating an old API is easier when callers can be migrated mechanically; see [[Deprecation]]. They can also break things in surprising ways, because callers rely on behaviors nobody intended to promise; see [[Hyrum's Law]]. A codemod that compiles everywhere still needs the full test suite; see [[Continuous Integration]].

The line between a codemod and an editor's refactoring command is mostly scale. An editor renames a symbol in one project; a codemod is written once and run across many repositories or the whole of a large one; see [[Refactoring]] and [[Software Rot]].
