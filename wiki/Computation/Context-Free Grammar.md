A **context-free grammar** is a set of rules for building strings in a language by repeatedly replacing a symbol with a sequence of other symbols. A grammar for arithmetic might say: an *expression* is a *number*, or an *expression* plus an *expression*, or an *expression* in parentheses. Applying rules over and over generates every valid expression, nested as deeply as needed; see [[Recursion]].

"Context-free" means each rule applies to a symbol regardless of what surrounds it. An *expression* can be expanded the same way whether it appears at the top level or deep inside parentheses.

Noam Chomsky introduced a classification of grammars in 1956, now called the **Chomsky hierarchy**, each level more powerful than the last and matched to a kind of machine that can recognize it:

- **Regular** languages, recognized by a [[Finite State Machine]] and described by a [[Regular Expression]]. They can't count or match nesting.
- **Context-free** languages, recognized by a machine with a stack, which can track nesting.
- **Context-sensitive** languages, recognized by a machine with bounded memory.
- **Recursively enumerable** languages, recognized by a Turing machine; see [[Turing Completeness]].

The stack is the key difference between the first two levels. A finite state machine can't recognize balanced parentheses, because it would need unbounded memory to count them. That's why regular expressions can't reliably parse nested formats such as HTML or [[JSON]], a limit programmers rediscover often.

Chomsky's motivation was linguistic: describing the structure of human sentences. In 1959–1960, John Backus and Peter Naur adapted grammar notation to define the programming language ALGOL, and **Backus–Naur form** (BNF) became the standard way to specify programming language syntax.

A **parser** takes a string and a grammar and builds the tree of rule applications that produced it, usually simplified into an [[Abstract Syntax Tree]]; see [[Compiler]] and [[Interpreter]]. Common approaches include:

- **Recursive descent**, one function per rule, easy to write by hand and used by many production compilers.
- **LR parsing**, generated by tools from a grammar, efficient and handling a wide class of grammars.
- **General algorithms** that handle any context-free grammar, including ambiguous ones, using [[Dynamic Programming]].

**Ambiguity** is a recurring problem. In the "dangling else" problem, `if a then if b then x else y` could attach the `else` to either `if`. Languages resolve it with a convention. Determining whether an arbitrary grammar is ambiguous is undecidable; see [[Halting Problem]].

Natural languages turned out not to be fully context-free; some, such as Swiss German, have crossing dependencies a context-free grammar can't express. Still, context-free grammars remain a useful approximation for much of linguistic structure, and nearly every programming language's syntax is defined with one.
