A **passkey** is a credential for signing in to a website that replaces the password with a key pair. The site stores a public key; your device keeps the matching private key and proves it holds it by signing a challenge. Nothing secret ever travels to the server or sits in its database. Passkeys are built on **WebAuthn**, a W3C browser standard from 2019, together with the FIDO Alliance's protocol for talking to hardware authenticators; the pair is called FIDO2.

Signing in works as challenge-response; see [[Public-Key Cryptography]]:

1. The server sends a random challenge.
2. The browser asks the authenticator, such as a phone or USB security key, to sign it.
3. The authenticator checks that you're present, usually with a fingerprint, face scan, or device PIN, then signs. The biometric never leaves the device.
4. The server verifies the signature with the stored public key.

The design fixes passwords' two worst failures.

**Phishing resistance.** Each passkey is bound to the domain that created it, and the browser enforces that binding. A convincing fake at `examp1e.com` can't request a signature for `example.com`, because the browser won't produce one. A password depends on the user noticing the wrong address; a passkey doesn't depend on the user noticing anything. Codes sent by text message or generated by an app can still be typed into a fake site and relayed in real time, so passkeys are stronger than most two-factor setups.

**Nothing to steal from the server.** A breach exposes public keys, which are useless to an attacker. There's no reused password to try on other sites, so credential stuffing stops working.

The private key lives in protected hardware, such as a [[Trusted Platform Module]] or a phone's secure chip. Early FIDO keys were bound to a single device, which made losing it painful. The term "passkey," adopted by Apple, Google, and Microsoft in 2022, usually means a *synced* credential: the platform's password manager copies the private key, end-to-end encrypted, across your devices. That trades some security for recoverability, which is what made mass adoption plausible.

Remaining problems:

- **Recovery.** If every device is lost, the fallback is often email or SMS, which reintroduces the weaker path attackers will target.
- **Portability.** Moving passkeys between ecosystems was long impossible; a credential-exchange standard is still rolling out.
- **Mental model.** Users understand passwords. A login with no secret to remember can feel like nothing happened, and inconsistent prompts across sites slow trust.

A passkey proves who you are; it doesn't decide what you may do. After sign-in, the site still issues a session, usually an [[HTTP Cookie]], and delegated access still runs through [[OAuth]]. The binding to a domain extends the browser's broader rule that credentials belong to an origin; see [[Same-Origin Policy]].
